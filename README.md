# HW-Authorization

Учебный проект: бэкенд на NestJS с авторизацией, загрузкой файлов в S3, кэшированием, транзакциями и фоновыми задачами.

## Запуск


npm install
cp .env.example .env    # подставить свои секреты
docker compose up -d    # база
npm run migration:run
npm run start:dev       # приложение


Swagger: http://localhost:3000/api

В проекте используется docker-compose.yml, который разворачивает 4 сервиса:

PostgreSQL — основная база данных.

MinIO — S3-совместимое хранилище для аватарок (доступно на localhost:9000, консоль на localhost:9001).

minio-init — одноразовый контейнер, который создает бакет avatars и настраивает политики доступа.

Redis — используется для кэширования (Cache Manager) и как брокер сообщений для фоновых задач (BullMQ).


Эндпоинты
Метод	Путь	Описание
POST	/auth/register	Регистрация, возвращает пару токенов
POST	/auth/login	Вход по логину и паролю
POST	/auth/refresh	Новая пара токенов по refresh
POST	/auth/logout	Выход (сброс refresh-токена)
GET	/profile/my	Свой профиль
PATCH	/profile/my	Изменить свои данные
PATCH	/profile/change-password	Смена пароля (требует старый пароль)
POST	/profile/transfer	Перевод денег другому юзеру (требует Idempotency-Key в headers)
DELETE	/profile/my	Мягкое удаление аккаунта
GET	/users	Список юзеров (page, limit, search)
GET	/users/active	Активные юзеры (больше 2 аватаров, есть описание)
POST	/avatars	Загрузка аватара (JPEG/PNG до 10 МБ)
DELETE	/avatars/:id	Мягкое удаление аватара
POST	/admin/cleanup/avatars	Ручной запуск очистки старых аватаров
Всё кроме /auth/* требует заголовок Authorization: Bearer <access_token>.

## Заметки по реализации

- Access и refresh подписываются разными секретами
- Пароль хранится как bcrypt-хеш, колонка помечена `select: false`
- Удаление мягкое: `deletedAt` вместо `DELETE`
- Свой профиль берётся из токена, поэтому в пути нет `:id`
- Уникальность email и login в базе проверяется без учета регистра и только для активных юзеров (частичный индекс `WHERE deletedAt IS NULL`), что позволяет регистрироваться заново после удаления аккаунта
- В S3 (MinIO) хранится только `objectKey` (путь к файлу), а не полный URL, чтобы можно было сменить хранилище без переписывания базы
- Загружаемые файлы проверяются по магическим байтам (а не по mimetype клиента), ограничены JPEG/PNG и размером до 10 МБ (Multer отдает 413)
- Переводы денег используют `Decimal.js` для точной математики (без ошибок с плавающей точкой) и `pessimistic_write` для блокировки строк от одновременных списаний
- Идемпотентность переводов защищена заголовком `Idempotency-Key` и уникальным индексом в БД, что спасает от двойного списания при повторных запросах или гонках
- Кэш (Redis) инвалидируется через версионирование ключей (при обновлении юзера меняется версия списка), а для защиты от «эффекта стада» реализован Single-flight (при Cache Miss в базу идет только 1 запрос)
- Фоновая очистка на BullMQ пачками удаляет из S3 и БД аватары, которые были помечены удаленными более 7 дней назад
- Логирование (Pino + CLS) прокидывает `x-request-id` в каждую строку лога и заголовки ответа, а также скрывает (Redact) пароли и токены
